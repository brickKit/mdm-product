# mdm/product 的设计

本页写这个组件为什么这样设计：术语、拥有的数据、状态与规则、命令与事件、实现状态与未决问题。写给要修改它的人与 AI。怎样使用、部署与配置在 `BRICKKIT.md`；代码在哪、怎样构建与测试、设计取舍在 `AGENTS.md`；跨组件的规则在装配项目的协议 02（来源）、协议 07（资格与解析）、协议 14（数量与单位、列表）。

## 边界

产品主数据：产品与分类、单位目录与换算、追踪政策、按法人的可售与可采购状态。有销售、采购、库存或制造业务的客户都需要。

| 不在这里 | 归谁 |
| --- | --- |
| 标准成本、计价政策 | `erp/costing`：产品只保留物理与交易属性 |
| 库存数量与流水 | `erp/inventory`（本组件只接收“已有流水”的标记） |
| 价格 | `erp/sales`、`erp/purchase` 的价格表 |
| 行业属性 | 扩展字段（协议 08） |

## 术语

| 业务叫法 | 定义 | 代码标识符 |
| --- | --- | --- |
| 产品种类 | 库存商品、服务、非库存物品；只有库存商品参与库存 | `kind`：`stock`、`service`、`non_stock`；回答里的 `stocked` |
| 基本单位 | 产品数量的基准单位 | `base_unit` |
| 单位目录 | 随组件提供的单位（UN/ECE 第 20 号建议的代码），按类别带对类别基本单位的系数与数量的小数位；包装单位没有系数 | `unit`；`category`：`count`、`mass`、`length`、`area`、`volume`、`time`、`package` |
| 产品专属换算 | 一个单位等于多少个本产品的基本单位（一箱等于多少件），优先于目录的通用换算 | `product_conversion` |
| 追踪政策 | 不追踪、批次、序列号 | `tracking`：`none`、`batch`、`serial` |
| 按法人开通 | 产品在一个法人下可售、可采购，各自开关 | `product_availability`（`sellable`、`purchasable`） |
| 已有流水 | 库存已有该产品的流水；之后追踪政策与基本单位不再改变 | `has_movements` |
| 条码 | 产品的条码（以后） | — |
| 资格 | 新单据能否在某法人以某用途（销售、采购）引用某产品；回答带是否参与库存与取证时刻 | `CheckEligibility` |

## 拥有的数据

| 表 | 内容 | 终态与保留 |
| --- | --- | --- |
| `unit` | 单位目录，迁移写入 | 只随新迁移增加 |
| `category` | 分类树：代码（唯一）、上级、启用 | 停用，不删除 |
| `product` | 产品：代码（唯一，永不复用）、种类、名称与译名、分类、基本单位、追踪政策、已有流水、状态 | `retired`；不删除 |
| `product_conversion` | 产品专属换算 | 随产品版本 |
| `product_availability` | 按法人的可售、可采购；法人是 `mdm/org` 的不透明引用 | 随产品版本 |

换算与开通是产品状态的一部分：产品连同它们一起版本化，一个事件就是产品的完整状态。

## 状态与规则

产品的状态与伙伴相同（`active`、`suspended`、`retired`，退役不可恢复）。不变量：

- 服务与非库存物品不追踪批次或序列号（数据库约束与接口校验都拒绝）。
- 已有流水的产品不能改追踪政策或基本单位：改用新产品并迁移。
- 换算经基本单位：任何两个单位先换成基本单位再换出去，产品专属换算优先；包装单位只能来自产品；结果按目标单位的小数位舍入。系数与数量都是十进制，不用浮点。
- 开通时在事务之外同步问 `mdm/org` 法人是否启用；不可达不等于不存在（协议 07）。
- 资格：产品 `active`、在该法人开通、用途对应的开关为真，才 `eligible`；否则答 `not_found`、`product_<状态>`、`not_opened`、`not_sellable`、`not_purchasable`。资格不看法人的状态（与伙伴相同，法人的证据由引用方另取）。W 是 30 秒，从引用方发出查询时算起。

## 命令与查询

| 命令或查询 | 用户面或系统面 | 权限键 |
| --- | --- | --- |
| 新建与修改产品；产品的状态；按法人开通 | 用户面 | `mdm.product.edit` |
| 读取与列出产品；单位目录；换算；资格 | 用户面 | `mdm.product.read` |
| 新建与修改分类 | 用户面 | `mdm.product_category.manage` |
| 列出分类 | 用户面 | `mdm.product.read`（分类资源的读取操作是 `mdm.product_category.read`，用于授权视图） |
| 来源方法 `Snapshot`、`Read`；资格；批量解析；换算 | 系统面 | `mdm.product.system.read` |

## 事件

流 `mdm.product`（4 个分区），完整状态：`mdm.product.changed.v1`（连同换算与开通）、`mdm.product_category.changed.v1`。销售、库存投影产品一份就够；资格判断走资格查询。

## 依赖

- `mdm/org`（必需）：开通时确认法人启用。
- 身份、授权（必需）；`infra/audit`（可选）。
- 第 7 步起订阅库存的流水事件，设置“已有流水”。

## 未决问题

- “已有流水”的标记由哪个库存事件设置、迟到时怎样处理（第 7 步与库存一起定）。
- 条码：全局唯一还是允许重复、码制与校验位（GTIN 等）、一个产品几个条码、包装层级（件、盒、箱）的条码挂在换算上还是单独一张表、停用产品的条码怎样处理；契约里的条码路由现在答“能力不支持”。

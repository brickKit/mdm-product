# internal/：业务模块

产品主数据的业务，每个模块一个包。只给本仓库引用（Go 的 `internal`）：别的组件编译期就引用不了，跨组件只走契约（决定 0101）。先按下表找到模块，再读那个目录的 `AGENTS.md`。

## 模块

| 包 | 一句话 | 依赖（本组件内） |
| --- | --- | --- |
| `products` | 产品：新建、修改、状态、按法人开通、列表；资格 | `core`、`units` |
| `categories` | 分类：新建、修改、列表 | `core` |
| `units` | 单位目录与换算 | `core` |
| `source` | 系统面：来源方法、资格、解析、换算 | `core`、`products`、`units` |
| `core`（共用） | 名字与资源定义、校验、十进制辅助、审计与事件、记录、`Base`、本版不做的路由 | — |

分层（每个包只引用比它低的层）：`source` → `products` → `units`、`categories` → `core`。

## 共同的写法

- 每个模块的函数先收 `m *core.Base`（运行时；来源方法盖戳用的部署与实现实例），入口包的 `Module` 持有它、登记时适配。
- 换算与开通是产品状态的一部分：产品连同子表一起读、一个事件发完整状态（`core.GetProduct`：先锁行，再读子表）。
- 写入、审计（`core.Change`）与发件表（`core.Emit`）同一个事务；内容相同不产生新版本（`core.Same`，按 JSON 比较）。
